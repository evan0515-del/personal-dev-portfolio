把 Server Components 仅仅理解成性能优化是远远不够的。更大的收益在于结构清晰。

## 从稳定部分开始

大部分页面都包含大量不需要浏览器运行时才能存在的内容。元数据、内容加载、初始数据获取，以及结构性导航，默认放在服务端通常更可靠。

## 有意识地加入交互

客户端代码应该因为用户真的需要交互才存在，而不是因为架构默认如此。主题切换、语言切换、过滤器、动效，这些都很适合作为客户端小岛。除此之外，组件应该能够说明自己为什么值得 hydration。

## 不止是更快

当服务端负责页面中更稳定的部分时：

- 数据依赖更容易追踪
- SEO 更接近真正需要它的路由
- 客户端包体更小
- 集成逻辑更容易缓存与测试

## 一个简单判断

如果组件主要负责读取数据和组织 UI，它大概率更适合放在服务端。如果它需要浏览器状态或高频交互，它才更适合放在客户端。只要这个边界被持续执行，架构就会越来越清楚。
